# 백엔드 코드 리뷰

실결제가 발생하는 상용 서비스의 백엔드를 리뷰한다. 아래 절차와 기준을 따른다.

## 절차

1. **먼저 변경 목적과 영향 범위를 파악한다.**
   diff만 보지 말고 관련 이슈/PR 본문, 호출부, 연관 모듈까지 확인해서
   "이 변경이 왜 필요하고 어디까지 영향을 주는가"를 리뷰 서두에 요약한다.

2. **정확성, 보안, 동시성, 트랜잭션, 성능, 예외 처리를 검토한다.**
   - 정확성: 상태 머신 전이 규칙, 경계값, null/undefined 처리
   - 보안: 인증/인가 누락, 입력 검증, 시크릿/개인정보 노출(로그 포함), 인젝션
   - 동시성: 동시 요청 레이스, 멱등성(특히 웹훅 이벤트ID UNIQUE), 중복 처리
   - 트랜잭션: 다중 쓰기의 원자성, 부분 실패 시 정합성, 트랜잭션 경계
   - 성능: N+1 쿼리, 인덱스 유무, 페이지네이션 누락, 불필요한 직렬 I/O
   - 예외 처리: 실패 경로의 사용자 응답, 재시도 가능성, 에러 삼킴 여부

3. **기존 테스트가 보장하지 못하는 엣지 케이스를 찾는다.**
   apps/api/test의 e2e 스펙을 확인하고, 이번 변경으로 새로 생기는
   미커버 경로(동시 호출, 실패 주입, 권한 경계)를 명시한다.

## 결과 보고 기준

- **반드시 수정할 문제와 개선 제안을 구분한다.** (🔴 필수 수정 / 🟡 개선 제안)
- **문제를 지적할 때 발생 조건과 수정 방향을 함께 제시한다.**
  "X가 위험하다"가 아니라 "조건 A에서 B가 발생한다 → C로 수정" 형태로.
- **근거 없는 칭찬과 단순한 취향 차이는 제외한다.**
  스타일 지적은 프로젝트 컨벤션(CLAUDE.md, 기존 패턴) 위반일 때만.
