# [블로그 초안] TypeScript 개념 노트

> 실전에서 마주친 TS 개념 정리. 데모 배포 중 서버 빌드 실패(TS2352)에서 출발.

## 타입 단언(as) — 컴파일러의 검사를 내 서명으로 대체하기

- `value as SomeType` = "이 값을 SomeType이라 치고 검사해라". **런타임에는 아무 일도
  일어나지 않는다** — 값 변환이 아니라 컴파일 타임 라벨 교체. 단언이 틀리면 컴파일은
  통과하고 런타임에 터진다
- 정당한 사용처: **타입 선언이 현실보다 좁을 때.** 예: BullMQ `queue.client`의
  `IRedisClient` 선언에는 ping이 없지만 실제 객체(ioredis)에는 있다
- **겹침(overlap) 검사**: 직접 단언은 두 타입에 접점이 있어야 허용된다. 공통 속성이
  하나도 없으면 TS2352("실수 아니냐") — `"abc" as number` 같은 헛소리를 막는 규칙
- **`as unknown as T` (이중 단언)**: unknown은 모든 타입 ↔ unknown 단언이 항상 허용되는
  "정체불명" 타입 — 겹침 검사를 우회하는 공식 탈출구. 에러 메시지가 직접 제안하는 형태로,
  "런타임 현실을 알고 책임진다"는 의도 표시를 두 번 하는 것
- 원칙: 최후의 수단, 최소 범위로 (`any`로 뭉개지 말고 필요한 속성만 — `{ ping(): ... }`)
- 실전 교훈: 직접 단언은 겹침 판정이라는 경계선 위 코드라 환경에 따라 판정이 갈릴 수
  있었다 (로컬 통과/서버 도커 빌드 실패). unknown 경유는 판정 자체가 없어 결정적 —
  "로컬에선 되는데"를 없애려고 도커를 쓰면서 코드가 그 원칙을 어기면 안 된다
